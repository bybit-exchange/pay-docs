## HTTP Request

GET `/v5/pay/agreement/transaction/query`

Query a single deduction transaction or refund record by its transaction or refund number. The current implementation determines the returned detail type from the matched order record.

---

## Request Parameters

| Parameter | Type | Required | Description |
|:----------|:-----|:---------|:------------|
| merchantId | string | **Yes** | Merchant ID |
| userId | string | No | Platform user ID; accepted by the interface but not used by the current query lookup |
| agreementType | string | **Yes** | Sign type: `CYCLE` / `NON_CYCLE` / `SINGLE`; accepted but not used by the current query lookup |
| recordType | string | No | Record type: `PAY` / `REFUND`; accepted but not used by the current query lookup, and no default is applied |
| tradeNo | string | Conditional | Platform trade number; provide at least one transaction/refund number |
| outTradeNo | string | Conditional | Merchant order number; provide at least one transaction/refund number |
| refundNo | string | Conditional | Platform refund number; provide at least one transaction/refund number |
| outRefundNo | string | Conditional | Merchant refund number; provide at least one transaction/refund number |

:::info
At least one of `tradeNo`, `outTradeNo`, `refundNo`, or `outRefundNo` must be provided.
:::

## Notes

- Use this API to confirm transaction or refund status after timeout
- The detail type is determined by the matched order and returned in either `tradeDetail` or `refundDetail`
- For `PROCESSING` status, wait for the webhook or poll periodically
