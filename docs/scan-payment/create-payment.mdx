### HTTP Request
POST `/v5/bybitpay/create_pay`

### E-Commerce Request

#### Request Parameters

| Parameter | Required | Type | Comments|
|:----- |:-------|:-----|------ |
|merchantId |**true** |string |Onboarding merchant UID|
|merchantName|false | string|If not filled in, we will show users the name of your company doing KYB on the Bybit platform|
|clientId |false|string |Merchant client ID|
|[paymentType](data-model/payment-type) | **true**|string |Payment type|
|customer |false|&lt;[CustomerType](data-model/customer)&gt; |Customer info|
|merchantTradeNo |**true**|string |Merchant order number|
|quotationId |false|string |Return result quotationId to create order|
|goods |**true**|array&lt;[GoodType](data-model/good)&gt; |Product description|
|orderAmount | **true**|string |Order amount|
|currency | **true**|string |Order currency (uppercase, e.g., `EUR`, `USD`, `USDT`)|
|currencyType |**true**|string |Currency type (`fiat` or `crypto`)|
|successUrl | **true**|string |URL to return after successful payment (max 256 characters)|
|failedUrl | **true**|string |URL to return after failed payment (max 256 characters)|
|webhookUrl |**true**|string |API URL to call when order is successful or failed (max 256 characters)|
|orderExpireTime | false|int64 |Order expiration time in UTC timestamp (second precision), default is 1 hour, max is 1 hour|
|env | **true**|&lt;[EnvType](data-model/env)&gt; |Transaction source|
|riskInfo |false|&lt;[RiskInfoType](data-model/risk-info)&gt; |Risk info for order pay|
|remark |false|string |Payment remark, max 50 characters|
|chainAddress |false|string |Chain address|
|chainType |false|string |The receiver's chain type (BSC/TRX/ARBI/LTC/SOL/ETH/TON/APTOS)|

### Auth Request

Auth reuses the Payment Creation endpoint. Set `paymentType` to `E_COMMERCE` and use `paymentMethod = AUTH` to distinguish this scenario from the existing E-Commerce Payment flow.
Fields not listed below follow the common Payment Creation definition above.

| Field Name | Type | Required | Description |
| --- | --- | --- | --- |
| `paymentType` | string | Yes | Must be `E_COMMERCE`. |
| `paymentMethod` | string | Yes | Must be `AUTH`. |
| `orderAmount` | string | Yes | Must be exactly `0`. Auth does not initiate a payment or asset transfer. |
| `goods` | array&lt;[`Good Type`](data-model/good)&gt; | No | Optional for Auth. If provided, each item follows the existing validation rules. |
| `env` | [`Env Type`](data-model/env) | Yes | Transaction Source. The validation rules are the same as the existing E-Commerce Payment flow. |
| `riskInfo` | [`RiskInfo`](data-model/risk-info) | No | Risk info for order pay |
| `customer` | [`Customer Type`](data-model/customer) | No | Customer info |
| `quotationId` | string | No | Not used in current use case |
| `chainAddress` | string | No | Not used in current use case |
| `chainType` | string | No | Not used in current use case |

`orderExpireTime` is the authorization confirmation deadline. It remains a UTC Unix timestamp in seconds, defaults to one hour, and cannot exceed one hour from order creation.

### Common Response

The response structure is shared by E-Commerce and Auth. For Auth, `result.order.amount` is `0` and `result.order.authStatus` is initially `PENDING`.

#### Response Parameters

| Parameter | Type | Comments|
|:----- |:-----|----- |
|payId |string |Pay-order ID created successfully|
|terminalType |string |Transaction source (APP, WEB, WAP, MINIAPP, OTHERS)|
|expireTime |number |Order expiration time in UTC timestamp (second precision)|
|checkoutLink |string |Unified checkout link in Bybit, redirect for payment|
|qrContent |string |QR code content (base64 Image, valid for 1 hour), developers generate QR image|
|order |&lt;[PayOrderType](data-model/pay-order)&gt; |Bybit pay order detail|
|customer |&lt;[CustomerType](data-model/customer)&gt; |Customer info|
