### HTTP Request
GET `/v5/bybitpay/pay_result`

### Request Parameters
| Parameter | Required | Type | Comments|
|:----- |:-------|:-----|------ |
|merchantId |**true** |string |Onboarding merchant UID|
|clientId |false|string |Merchant client ID|
|[paymentType](data-model/payment-type)|**true** |string|Payment type|
|merchantTradeNo|false |string|<li>"paymentType"=`E_COMMERCE`: it is merchant order number; "paymentType"=`E_COMMERCE_REFUND`: it is merchant refund order number</li><li><b>required</b> if "payId" is not provided</li>|
|payId|false |string|<li>"paymentType"=`E_COMMERCE`: it is Bybit pay ID; "paymentType"=`E_COMMERCE_REFUND`: it is Bybit refund ID</li><li><b>required</b> if "merchantTradeNo" is not provided</li>|

### Response Parameters
| Parameter | Type | Comments|
|:----- |:-----|----- |
|order |&lt;[PayOrderType](data-model/pay-order)&gt; |Bybit PayOrder Detail|
|customer |&lt;[CustomerType](data-model/customer)&gt; |Customer info|

Host: api2.bybit.com
X-BAPI-SIGN: XXXXX

X-BAPI-RECV-WINDOW: 5000

### Auth

Auth reuses the Payment Result endpoint. The query parameters remain unchanged: use `paymentType = E_COMMERCE` and provide either `payId` or `merchantTradeNo`. Using `payId` is recommended.
The response adds the following fields:

| Field Name | Type | Required | Description |
| --- | --- | --- | --- |
| `result.order.authStatus` | string | Yes | Current authorization status. |
| `result.order.authExpireAt` | string | No | Authorization expiry time as a UTC Unix timestamp in milliseconds. Returned after authorization succeeds. |
| `result.customer` | [`Customer Type`](data-model/customer) | No | Authorized customer fields. Returned only when `authStatus` is `SUCCESS` and the authorization has not expired. |

Authorization status:

| `authStatus` | Order `status` | Description |
| --- | --- | --- |
| `PENDING` | `INIT` | Waiting for the user to agree to or reject the authorization request. |
| `SUCCESS` | `PAY_SUCCESS` | The user agreed and the authorization is still valid. Authorized customer fields may be returned. |
| `REJECTED` | `ERROR` | The user rejected the authorization request. |
| `OVERTIME` | `TIMEOUT` | The user did not complete authorization before `orderExpireTime`. |
| `EXPIRED` | `PAY_SUCCESS` | The user previously agreed, but the authorization validity period has ended. The original order remains successful and customer fields are no longer returned. |

`authStatus` is the authoritative authorization status. The existing order `status` continues to represent the payment-order result.
The actual `customer` fields are determined by the merchant's current authorization package:

| Authorization Field | Response Field | Description |
| --- | --- | --- |
| `uid` | `customer.uid` | Bybit user UID. |
| `legalIdNumber` | `customer.legalIdNumber` | Legal identity document number. |
| `idType` | `customer.idType` | Legal identity document type. |
| `fullName` | `customer.firstName`, `customer.lastName` | Customer's first and last name. |
| `birthdate` | `customer.dateOfBirth` | Date of birth. |
| `kyc1Country` | `customer.kyc1Country` | KYC Level 1 country or region code. |
| `email` | `customer.email` | Email address. |
| `phoneNumber` | `customer.phone` | Phone number, including the country calling code when available. |

`legalIdNumber` and `idType` are returned as a pair from one complete identity-document source.
